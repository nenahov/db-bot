# Бот для работы с БД

Telegram-бот — клиент для **PostgreSQL** и **ClickHouse**. Сохраняет подключения, выполняет SQL и показывает результат таблицей прямо в чате.

Отправьте запрос одним сообщением — бот выполнит его на активном подключении.

## Возможности

- Подключения PostgreSQL и ClickHouse: создание, редактирование, удаление, переключение активного
- Пароли хранятся в SQLite в зашифрованном виде (Fernet)
- SQL в чате: превью таблицы, повторный запуск, выгрузка CSV
- Избранные запросы — по текущему подключению или списком всех
- Импорт карточки подключения: переслали карточку → бот просит только пароль
- Лимиты: таймаут запроса, число строк в превью и в полной выборке
- Метаданные бота — в локальном SQLite, логи — в файл с ротацией

## Требования

- Python 3.11+
- Токен Telegram-бота ([@BotFather](https://t.me/BotFather))
- Сетевой доступ с машины бота до хостов БД (порты по умолчанию: PostgreSQL `5432`, ClickHouse HTTP `8123`)

## Быстрый старт

```bash
git clone https://github.com/nenahov/db-bot.git
cd db-bot

python -m venv .venv
# Windows:  .venv\Scripts\activate
# Linux/macOS:  source .venv/bin/activate

pip install -r requirements.txt
```

Скопируйте пример конфига и заполните секреты:

```bash
# Windows
copy .env.example .env

# Linux/macOS
cp .env.example .env
```

В `.env` обязательны `BOT_TOKEN` и `ENCRYPTION_KEY`. Ключ шифрования:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Запуск:

```bash
python -m bot
```

Бот работает в режиме polling. SQLite (`data/bot.db`) и каталог логов создаются автоматически.

## Конфигурация

| Переменная | Описание | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | Токен Telegram-бота | — |
| `ENCRYPTION_KEY` | Ключ Fernet для паролей подключений | — |
| `SQLITE_PATH` | Файл SQLite с пользователями, подключениями и избранным | `./data/bot.db` |
| `QUERY_PREVIEW_ROWS` | Сколько строк показать в таблице в чате | `50` |
| `QUERY_MAX_ROWS` | Максимум строк, которые бот заберёт из БД | `50000` |
| `QUERY_TIMEOUT_SEC` | Таймаут выполнения SQL, секунды | `60` |
| `RESULT_CACHE_TTL_SEC` | Сколько секунд хранить результат для CSV / «Обновить» | `3600` |
| `LOG_DIR` | Каталог логов | `./logs` |

Не коммитьте `.env`. Ключ `ENCRYPTION_KEY` нельзя менять, если в базе уже есть сохранённые подключения: пароли перестанут расшифровываться.

## Как пользоваться

Команды бота:

| Команда | Действие |
|---|---|
| `/start`, `/menu` | Главное меню |
| `/connections` | Список подключений |
| `/favorites` | Избранные запросы |
| `/current` | Текущее активное подключение |

### Подключения

1. Откройте «Подключения» и добавьте PostgreSQL или ClickHouse (имя, хост, порт, БД, пользователь, пароль).
2. Выберите режим SQL: **только чтение** или **чтение и запись**. Режим можно потом сменить в карточке подключения.
3. После сохранения бот проверяет доступ (`SELECT 1`) и делает подключение активным.
4. Дальше любой текст, который не является командой, считается SQL и уходит в активную БД.

Карточку подключения можно переслать боту — он распознает поля и спросит пароль. Если в карточке нет строки «Режим SQL», импорт сохраняется **только для чтения**. Явно указать запись:

```text
prod-pg
Тип: postgres
Хост: db.example.com:5432
БД: analytics
Пользователь: readonly
Режим SQL: чтение и запись
```

### Запросы

Результат с колонками приходит HTML-таблицей. Если строк больше превью — в чате первые N, полный набор — кнопкой «Скачать CSV».

Кнопки после запроса:

- **Обновить** — выполнить тот же SQL ещё раз
- **Скачать CSV** — файл с выборкой из кэша
- **В избранное** — сохранить SQL с названием

Запросы без набора строк (например `UPDATE`) показывают время выполнения и число затронутых строк.

### Избранное

Избранные запросы привязаны к подключению. Можно смотреть только текущее подключение или все сразу, запускать и удалять.

## Безопасность

- Пароли подключений шифруются перед записью в SQLite; в карточках в чате пароль не показывается.
- У подключения есть флаг **только чтение** (по умолчанию для уже сохранённых и для импорта без явного режима): для PostgreSQL сессия идёт с `default_transaction_read_only=on`, для ClickHouse — `readonly=1`. Это ограничение сессии, не замена прав в БД: для продакшена лучше отдельная учётка с минимальными правами.
- Если флаг выключен, бот выполняет любой SQL от имени сохранённого пользователя БД, включая изменение и удаление данных.
- Подключения изолированы по `telegram_id`: чужие базы в боте не видны.
- Бот должен иметь доступ к хостам БД. Не публикуйте его в интернет без понимания, кто сможет писать ему SQL.

## Стек

- [aiogram](https://docs.aiogram.dev/) 3 — Telegram Bot API
- SQLAlchemy 2 + aiosqlite — хранилище бота
- asyncpg — PostgreSQL
- clickhouse-connect — ClickHouse
- pydantic-settings — конфигурация из `.env`
- cryptography (Fernet) — шифрование паролей

## Структура

```text
bot/
  handlers/     команды и колбэки (меню, подключения, запросы, избранное)
  services/     SQL, шифрование, кэш результатов, карточки подключений
  db/           модели и репозитории SQLite
  keyboards/    инлайн-клавиатуры
  middlewares/  сессия БД и логирование действий
  states/       FSM-формы
  config.py     настройки из окружения
  main.py       запуск polling
```
